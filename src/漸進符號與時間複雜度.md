# 漸進符號與複雜度筆記

## 漸進符號 (Asymptotic Notation)
- 是一種用來描述演算法執行時間或空間需求隨輸入規模成長的數學記號
- **Big O (O)**
  - 代表演算法複雜度的上限 (Upper Bound)
  - 主要用來評估演算法在最壞情況下的表現
  - 是實務上最常用來衡量演算法好壞的指標
- **Omega (Ω)**
  - 代表演算法複雜度的下限 (Lower Bound)
  - 用來評估演算法在最好情況下的表現
- **Theta (Θ)**
  - 代表演算法複雜度的確切界限 (Tight Bound)
  - 必須同時滿足時間複雜度達到上限與下限時才能使用

## 時間複雜度 (Time Complexity)
- 衡量演算法執行所需時間隨著輸入資料量 (n) 增加時的成長趨勢
- **O(1) 常數時間**
  - 運行時間始終固定，不會受輸入資料量多寡影響
  - 例子：透過索引取得陣列元素、Hash Table 的基礎增刪查
- **O(log n) 對數時間**
  - 在每次操作中都能將需要處理的資料量按比例縮減 (如減半)
  - 例子：二元搜尋 (Binary Search)、二元搜尋樹的操作
- **O(n) 線性時間**
  - 執行時間與輸入資料量成正比
  - 例子：使用單層迴圈走訪整個陣列或鏈結串列
- **O(n log n) 線性對數時間**
  - 結合了線性與對數的特徵，常見於分治法 (Divide and Conquer)
  - 例子：合併排序 (Merge Sort)、快速排序 (Quick Sort) 的平均情況
- **O(n^2) 平方時間**
  - 執行時間與輸入資料量的平方成正比，處理大數據時效能極差
  - 例子：使用雙層迴圈 (如氣泡排序 Bubble Sort、選擇排序 Selection Sort)

## 空間複雜度 (Space Complexity)
- 衡量程序在執行過程中所需要消耗的額外記憶體空間
- **O(1) 常數空間**
  - 演算法只需使用固定數量的變數或暫存空間，不需隨著資料量增加而配置更多記憶體 (就地執行 In-place)
- **O(n) 線性空間**
  - 需要配置與輸入資料量等比例的額外儲存空間
  - 例子：將資料複製到另一個長度為 n 的新陣列，或遞迴深度展開到 n 層造成的 Call Stack 堆疊消耗
