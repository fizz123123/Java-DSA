# 掌握遞迴思維與追蹤技巧 (Recursion Tracker Cheat Sheet)

理解遞迴(Recursion) 的運作是資料結構(特別是 Tree 和 Graph) 中最容易卡關的地方，迴圈是「平鋪直敘」的，而遞迴是「有深度」的

以下整理了四個實用的遞迴思考心法

---

## 技巧一：信仰之躍 (The Leap of Faith)
**「不要試圖在大腦中追蹤整個遞迴展開的過程」**
人類的短暫記憶有限，硬要在大腦裡展開多層呼叫會導致當機

只需要確認兩件事，然後 "相信" 遞迴會自己搞定剩下的事：
1. **Base Case（終止條件）對了嗎？**
   * 例：遇到 null 代表到底了 `if (currentNode == null) return null;`
2. **單一步驟（當前節點）的邏輯對了嗎？**
   * 只要當前節點做的事情是對的，剩下的就交給遞迴。把程式碼解讀為**分派任務**，而不是去想子任務怎麼執行

---

## 技巧二：拆解成「遞進 (Winding)」與「回溯 (Unwinding)」
遞迴是 **「去程 (往下找)」** 跟 **「回程 (往上接)」** 的結合

以 Binary Search Tree 的新增方法 `rInsert` 為例：
```
currentNode.left = rInsert(currentNode.left, value);
return currentNode;
```
1. **遞進 (Winding)：** 尋找正確的位置，不斷往下一層呼叫，此時還沒有任何節點被真正接上，大家都在等
2. **觸底 (Base Case)：** 遇到 `null`，執行 `return new Node(value);`（生出新節點，準備回程）
3. **回溯 (Unwinding)：** 上一層的 `currentNode.left` 接到了剛剛回傳的新節點，然後繼續執行 `return currentNode;` 告訴更上一層：我接好了

> **口訣：** 
> 在操作 Tree 的遞迴時，`return currentNode;` 就是在對上一層的 Parent 說：
> **「我處理好我的子樹了，這是我現在完整的樣子，請把我接回去」**

---

## 技巧三：拿最極簡的範例畫圖 (3個節點)
當遇到複雜代碼需要 Trace Code 時，**絕對不要**拿超過 4 個節點以上的樹去追蹤

1. 在紙上畫一棵只有 **3 個節點**的樹（例如 `Root=10`, `Left=5`, `Right=15`）
2. 想像你要刪除 `5`：
   * **Root(10) 層**：因為 5 < 10，執行 `10.left = deleteNode(5, 5)`。這時把 10 暫停，視角切換到 5
   * **Node(5) 層**：找到目標了，它沒有子節點，觸發回傳 `return null`
   * **回到 Root(10) 層**：收到回傳值，於是 `10.left = null`。最後 Root(10) 執行 `return 10`
   * **結束**：大功告成

## 技巧四：用語意化的問題來代替程式碼思考
將生硬的程式碼轉成「白話文」，用人類的邏輯來理解呼叫

* **問自己 `deleteNode(Node node, int value)` 的語意是什麼？**
  * 從 `node` 這棵樹中把 `value` 刪掉，並把 "刪除後的這棵樹的新 Root 還給我"

* **套用在難解的程式碼上：**
  ```
  // 刪除有兩個子節點的目標時：
  currentNode.right = deleteNode(currentNode.right, subTreeMin);
  ```
  * **白話文解讀：** 我的右子樹，請自己去把你裡面那個 `subTreeMin`  給刪掉，然後把你 "全新的右子樹" 交給我，我(`currentNode`) 會用我的 `right` 手臂重新牽住你

  * **白話文解讀：** 我的右子樹，請自己去把你裡面那個 `subTreeMin`  給刪掉，然後把你 "全新的右子樹" 交給我，我(`currentNode`) 會用我的 `right` 手臂重新牽住你
