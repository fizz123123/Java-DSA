# Hash Table (雜湊表) 筆記

## 基本概念
- 透過雜湊函數 (Hash Function) 將 Key 轉換成特定的陣列索引 (Index) 以儲存對應的資料
- 當不同的 Key 經過雜湊運算後得到相同的索引時，就會發生雜湊碰撞 (Hash Collision)
- 常見解決碰撞的方式為 Separate Chaining (鏈結法)，在同一個陣列索引位置使用鏈結串列來存放多筆資料
- 經常搭配質數 (Prime Number) 參與雜湊函數的運算，能有效減少碰撞發生的機率

## 常見操作與時間複雜度
- **新增與修改 (put): O(1)**
  - 計算出索引後直接放入
  - 若該索引已有資料，則遍歷該位置的鏈結串列，找到相同的 Key 即更新 Value，否則新增節點至尾端
- **尋找 Key (如 get, containsKey): O(1)**
  - 能夠透過雜湊函數直接算出身分證 (Hash Code) 並對應到陣列索引，不需要逐一檢查所有元素，速度極快
  - 但在極端情況下 (所有資料都碰撞在同一個索引的鏈結串列上) 可能退化成 O(n)
- **尋找 Value (如 containsValue): O(n)**
  - Hash Table 沒有針對 Value 建立任何索引或 Hash
  - 若要找特定的 Value，唯一的方法就是走訪整個 Hash Table 內的所有配對直到找到為止

## 實作細節與邊界條件
- 底層通常使用一個陣列 (陣列中存放 Node 的 Reference) 來做為主要的儲存空間
- 實作 put 方法尋找同一個 bucket 的節點時，務必使用 `key.equals(temp.key)` 來確認是否為相同的 Key，以決定是更新既有的值還是新增節點
- 尋找全部的 Keys 時，需要使用雙層結構來遍歷：外層走訪陣列的每個索引，內層走訪每個索引對應的鏈結串列
